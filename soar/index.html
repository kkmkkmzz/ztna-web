SOAR · Security Orchestration, Automation and Response

SOAR란 무엇인가요

보안 경보가 울렸을 때 사람이 매번 손으로 하던 조사와 조치를, 미리 정한 절차대로 자동으로 이어 주는 도구입니다.

비유로 이해하기

화재 경보가 울리면 방화문이 자동으로 닫히고 관리실에 연락이 가는 건물 방재 시스템과 비슷합니다. 다만 "건물 전체 대피"처럼 큰 결정은 관리자가 직접 버튼을 누릅니다.

어떤 문제를 해결하나요

경보 홍수

하루에 쌓이는 경보가 사람이 하나하나 볼 수 있는 양을 넘습니다.

반복 작업

경보마다 같은 조회, 복사, 붙여넣기를 되풀이합니다.

흩어진 도구

조사 한 번에 여러 시스템을 오가야 합니다.

어떻게 동작하나요

  1. 경보 접수예: "평소와 다른 나라에서 로그인 시도" 경보가 들어옵니다.
  2. 정보 자동 수집접속한 IP의 평판, 사용자 정보, 기기 상태를 자동으로 조회합니다.
  3. 규칙으로 판단미리 정한 규칙에 따라 위험도가 높은지 낮은지 나눕니다.
  4. 사람 승인계정 잠금처럼 업무에 영향이 큰 조치는 담당자가 승인합니다.
  5. 조치와 기록승인된 조치를 실행하고, 처리 내역을 티켓으로 남깁니다.

직접 해 보기: 경보 하나가 처리되는 과정

"다음 단계"를 눌러 플레이북을 한 단계씩 진행해 보세요. 4단계에서는 여러분이 담당자로서 승인 여부를 정합니다.

시뮬레이션: 가상의 경보와 사용자로 만든 예시이며, 실제 제품의 동작이나 성능이 아닙니다.

    핵심 기능

    플레이북

    경보 종류별로 무엇을 어떤 순서로 할지 적어 둔 절차서입니다.

    시스템 연동

    계정 관리, 방화벽, 메일 등 여러 시스템에 명령을 보냅니다.

    사례 관리

    한 사건에 관련된 경보와 조치를 한곳에 모아 관리합니다.

    승인 단계와 기록

    자동으로 할 일과 사람이 결정할 일을 나누고 모든 과정을 남깁니다.

    자주 헷갈리는 질문

    SOAR와 SIEM은 무엇이 다른가요?

    SIEM은 여러 시스템의 기록을 모아 이상한 점을 찾아 경보를 만드는 쪽이고, SOAR는 그 경보를 받아 조사와 조치를 실행하는 쪽입니다. 요즘은 한 제품에 둘을 합치는 경우도 많습니다.

    SOAR는 AI인가요?

    기본적으로는 아닙니다. 사람이 정한 절차를 그대로 실행하는 자동화 도구입니다. 무엇을 할지 스스로 고르는 일은 AI SOC 쪽에서 다룹니다.

    자동화하면 오탐 때문에 정상 업무가 막히지 않나요?

    그럴 수 있습니다. 그래서 업무 영향이 큰 조치는 사람 승인 단계를 두고, 자동 실행은 영향이 작은 조치부터 시작하는 것이 일반적입니다.

    플레이북은 누가 만드나요?

    보안 운영 담당자가 평소 처리 절차를 정리해 만듭니다. 절차가 정리되어 있지 않은 조직은 자동화 전에 절차 정리부터 해야 합니다.
